# Security policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability or include secrets,
peer credentials, wallet material, private model URLs, or user data in a report.

Use GitHub's private vulnerability reporting for this repository:

<https://github.com/unstoppable-stack/unstoppable-dev/security/advisories/new>

Repository administrators must verify that private vulnerability reporting is
enabled and complete a test submission before public launch. If that page is
not available, pause the report rather than disclosing details publicly; the
project does not yet publish a fallback security email.

Include the affected package and version/commit, impact, reproduction steps,
and any suggested mitigation. Use minimal synthetic data.

## Release scope

Only versions and platforms listed in the current release record are in the
preview support scope. Deferred and planned packages still accept useful
reports, but may not receive a release on the same schedule.

## Disclosure

Please allow maintainers time to reproduce and coordinate a fix before public
disclosure. A named security/triage owner and response targets are still a
public-launch gate and will be added here once assigned.
