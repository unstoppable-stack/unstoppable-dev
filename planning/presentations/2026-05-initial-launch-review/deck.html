Executive Decision

We have enough product for an initial launch

  • A static website that explains the stack and gets developers started
  • A publishable CLI with project init, scaffolding, doctor checks, and Node control
  • Three app generators: Pear Desktop, Expo Mobile, Node CLI
  • A usable personal Node: data sync, file sync, delegated AI, desktop dashboard
  • An agent pack that teaches Claude, Cursor, OpenCode, and Codex the stack

But we should not launch until these are fixed

  • CLI still reports 0.2.0; launch deck and package versions must agree
  • Public docs contain stale flags: p2p, kv-storage, multi-writer
  • Website says products like Search/Agent are launch-ready, but they are not npm launch items
  • No launch changelog exists yet
  • Real-device mobile QVAC remains a confidence gate, not yet shown in this review

CLI: What Is User-Facing

Default npm profile

  • us init: bootstrap project + assistant config
  • us scaffold app: generate runnable app
  • us scaffold list-platforms and list-features
  • us doctor: platform-specific environment check
  • us node start/status/stop: friendly wrapper for local Node

Not launch-default

  • us remote: full-profile internal/preview feature
  • us research: maintainer validation tool
  • us search: promising, but not day-one public package story
  • Do not market these as install-and-run launch features unless publishing the full profile intentionally

Unstoppable Node

Data + files

  • App pairing over local Hyperswarm discovery topic
  • Hypercore/Hyperbee replication through shared Corestore
  • Hyperdrive registration and replication
  • Per-app pause/resume, storage usage, advisory quotas

AI provider

  • --ai-mock for demos and deterministic tests
  • --ai and --ai-model for QVAC-backed inference
  • Streaming inference protocol via NodeClient.requestInference()
  • Apps can require services.ai and fail fast

Operations

  • us node start/status/stop
  • Headless daemon host for CI/smoke tests
  • JSON export/import for config, registry, and trust decisions
  • Typed client errors and reconnect backoff

Node Desktop Dashboard

Launch-facing value

  • Visual proof that the Node is real and local
  • Shows apps, cores, drives, peers, service state, and event log
  • Trust-on-first-use approval flow and persistent decisions
  • Live AI toggle, app pause/resume, and data peek are implemented in current status

Positioning

  • Package is private: unstoppable-node-desktop@0.1.0
  • Launch it as a demo/control panel, not as an npm package promise
  • README is stale and still says approval flow is future work
  • Need a clean public run instruction before linking from website

Agent Pack

What users experience

  • Generated projects include assistant-specific rules and skills
  • Supported surfaces: Claude, Cursor, OpenCode, Codex
  • Skills cover app setup, P2P, storage, QVAC chat/RAG/vision/transcription/plugin patterns, wallet stubs
  • Canonical source and CLI-bundled copy are byte-identical

Launch constraints

  • Coverage is strong for scaffold + P2P + QVAC basics
  • WDK payments remain stub/docs gap, not a launch capability
  • Some planning docs undercount current skills/recipes and should not be used as public copy
  • Auto-activation/tooling is improving, but launch value is the bundled knowledge

Website

Ready surfaces

  • Landing page: value pillars, install CTA, modules, ecosystem
  • Getting Started: install, scaffold, assistant setup, Node connection
  • Docs: products, modules, quick links
  • Roadmap: workstreams, phases, Node architecture, coverage
  • Showcase placeholder is acceptable if clearly framed

Must fix before launch

  • Homepage/getting-started still show old scaffold flags
  • Roadmap labels are stale: CLI/Agent Pack shipped, Node status older than current repo
  • Docs market Search and Agent too strongly relative to npm launch scope
  • Add SEO/Open Graph basics and real launch wording instead of "early development" if public

What We Should Not Overclaim

Do not sell as shipped

  • WDK payments: generator emits stubs; SDK integration is not validated
  • Unstoppable Search as a public launch product: full-profile/local preview only
  • Unstoppable Agent as launch-quality coding agent: architecture exists, model quality remains the blocker
  • Expo Go support: mobile requires custom dev client/native build

Phrase as preview/alpha

  • Expo Mobile + local AI: alpha, with simulator smoke and optional real-device run
  • Node Desktop: control panel/demo until public distribution path is settled
  • Real QVAC model flows: supported, but large-model/device-dependent
  • Remote coder: internal/full-profile preview unless separately launched

Final Preflight

Required before public launch

  • Update website launch copy and remove stale feature flags
  • Update CLI README feature matrix and profile table to include us node
  • Bump CLI version and stop hardcoding stale version in src/us.ts
  • Add root or package changelog
  • Run builds/tests/pack again, then publish npm packages
  • Deploy website and test install commands from a clean machine

Recommended confidence gates

  • Real-device Expo Mobile local AI run
  • Manual demo: Pear Desktop scaffold + Node sync + desktop dashboard
  • Manual demo: Node CLI scaffold + us node start --ai-mock + streaming inference
  • Smoke generated assistant configs for one tool each: Claude, Cursor, OpenCode, Codex
