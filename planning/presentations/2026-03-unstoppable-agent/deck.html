Key Learnings: Hermes Agent

Agent Loop (ReAct Pattern)

  • Shared iteration budget across parent + child agents
  • Tool registry — tools self-register with schema + handler
  • Composable toolsets — "web", "terminal", "skills", etc.
  • Context compression when context gets large
  • Budget pressure — warns LLM at 70% / 90% of iterations
  • Fallback model — auto-switch on rate limits

Skill Creation Triggers

  • Complex task succeeded (5+ tool calls)
  • Errors were overcome
  • User-corrected approach worked
  • Non-trivial workflow discovered

P2P Data Model

Shared Skills

HyperDB: /skills/{hash}/
├── SKILL.md      # Full content
├── metadata      # name, desc, tags
├── author        # Peer public key
├── version       # Semver
└── content_hash  # Integrity

Feedback

HyperDB: /feedback/{skill}/{peer}
├── rating     # 1-5 stars
├── comment    # What happened
├── context    # Task description
├── outcome    # success/partial/fail
└── model_used # Which model

Troubleshooting Tips

HyperDB: /tips/{skill}/{id}
├── title     # Short summary
├── problem   # What went wrong
├── solution  # How to fix
├── platform  # macos/linux/win
└── model     # Which model worked

AutoResearch: Distributed P2P Research

Karpathy's Pattern (35k stars)

Agent reads program.md (a skill!), modifies code, runs 5-min experiments, keeps or discards based on metrics. Loops forever.

1. Read program.md (experiment instructions)
2. Modify target code with an idea
3. Run experiment (fixed time budget)
4. Evaluate metric — keep or discard
5. Repeat forever until human stops

Key insight: program.md is a skill. Humans write Markdown instructions, agent does the work.

Our P2P Extension

Distributed Autonomous Research

Multiple machines run experiments overnight. Results shared via HyperDB. No central server.

User A runs experiments overnight
      ↓
Results → HyperDB /research/{topic}/
      ↓
User B discovers: "15% better config!"
      ↓
User B applies + runs more experiments
      ↓
Collective improvement via P2P

Model Improvement Pipeline

Trajectories from real coding → training data → autoresearch loop → better local models → shared via Hyperdrive

AutoResearch: Beyond Training

The modify → run → evaluate → keep/discard pattern works for anything measurable:

🧪

Optimize Model Configs

Test quantizations, context lengths, batch sizes. Find the fastest config for your hardware.

✅

Benchmark Skills

Test if a skill works with different models. Auto-discover which model + skill combos are best.

🔧

Improve Code

Agent writes code, runs tests, keeps passing changes. Autonomous refactoring + optimization.

📊

Train Better Models

Use coding trajectories as training data. AutoResearch loop fine-tunes better local models.

The meta-play: Our agent uses autoresearch to improve itself — optimizing its own skills, model configs, and eventually training the next generation of local models. All shared P2P. Self-improving infrastructure.
