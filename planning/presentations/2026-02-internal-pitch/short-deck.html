Vibe-Coding Has Changed Everything

In the last months I've been building apps with AI assistants.
The speed is unreal.

Yoga Studio App

Built for my mom in Chile. Class management, attendance, payments. Built in hours — not weeks.

Personal Finance App

Expenses, income, Bitcoin tracking. Same approach — describe what I want, get working code.

AI assistants like Claude and Cursor are incredibly good at building apps with React, Next.js, Postgres, Stripe...

Any developer can build a full-stack centralized app in minutes.

But Not With Our Stack

Then I tried building with Holepunch + QVAC + WDK. The same AI falls apart.

P2P / Platform

  • Doesn't know which libraries to pick — dozens of Holepunch modules, AI can't find the simplest path
  • Node / Bare incompatibilities — uses Node APIs that don't exist in Bare runtime
  • Can't set up a Pear Desktop app — worker process, React, TypeScript, build pipeline
  • Wrong package versions — guesses versions that don't exist

AI / QVAC

  • Doesn't handle context overflow — hits token limits, no trimming strategy
  • Streaming done wrong — drops chunks, breaks UI updates
  • Think tags not handled — raw <think> tags leak into user UI
  • Vision, TTS, transcription? — hasn't even been tried, more trial & error ahead
If developers can vibe-code any app with a regular stack but can't with ours — they won't adopt our technologies.

The Adoption Risk

Centralized (React / AWS) Our Stack (Holepunch / QVAC / WDK)
AI builds it correctly? Yes, effortlessly No, constant errors

Adoption trend Accelerating At risk

Our stack has a structural advantage — no servers, no infra costs, private by default. But none of that matters if AI can't help developers use it.

Every day AI gets better at centralized — the gap widens.

How I Proved It Works Part 1 — CLI

I built the same app — Coffee Assistant — multiple times.

CLI App — 3 attempts before it worked

Two P2P terminal apps with AI: Hyperswarm + bare-rpc + QVAC + Hyperbee.

Attempt 1: Complete failure. AI couldn't set up P2P.

Attempt 2: Partial. Got stuck on RPC + streaming.

Attempt 3: Finally working after dozens of prompts and heavy debugging.

After getting it working, I asked the AI to identify reusable modules — extract patterns that could be reused across any app.

This became the first seed of the agent pack knowledge.

At this point I realized: if it's this hard for me, no other developer would even try.

How I Proved It Works Part 2 — Desktop

Desktop App — Attempt 1

Same app as Pear Desktop + React UI.

Setting up Pear was extremely difficult. I had to point the AI to the QVAC Workbench app as a reference just to get the project scaffolded.

Most devs won't have a reference app to copy from.

At least the AI could reuse the P2P logic from the CLI — that knowledge carried over.

This time I had a better process — documenting every fix as I went, extracting patterns systematically.

Desktop App — Attempt 2

How the Knowledge Is Built

Not docs from docs. Patterns extracted from real, working apps.

Build real app → hit bugs → document every fix → extract into agent pack ↓ Scaffold fresh project → vibe-code same app ↓ Works first try? → Knowledge validated ✓ Fails? → Fix gaps, repeat

The agent pack today:

  • 12 module docs (Pear, Bare, QVAC, WDK...)
  • 10 skills with full code examples
  • 18 recipes for common patterns
  • 8 reusable TypeScript components
  • Pinned, verified package versions
  • Real error messages → real fixes

Works with Claude Code, Cursor, and OpenCode. Same knowledge, adapted per tool.
